A client component calls useSearchParams() from next/navigation, and an App Router page or layout renders it with no Suspense boundary in between, while that page (or a page under that layout) is statically rendered.

Why is this an issue?

A static page is rendered at build time, when there are no search parameters. Next.js then renders the client component tree up to the closest Suspense boundary in the browser only. Without a boundary that is the whole page: the server HTML is empty and the build fails with "useSearchParams() should be wrapped in a suspense boundary".

The rule follows JSX from the page or layout to the component. It stays silent when any module on the way mentions Suspense, when a loading file wraps the page or the layout, when the component is loaded with next/dynamic, and when the page is dynamic: a dynamic segment without generateStaticParams, cookies(), headers(), a session helper, searchParams, dynamic = 'force-dynamic', no-store or revalidate = 0 in the page, its layouts or the server modules they import.

How to fix it

Wrap the component that reads the search parameters in <Suspense> with a fallback, as close to it as possible, so the rest of the page is still rendered on the server. Or read searchParams in the page and pass the values down.

Noncompliant code example

// components/Filters.tsx
'use client';
import { useSearchParams } from 'next/navigation';

export function Filters() {
  const color = useSearchParams().get('color'); // Noncompliant
  return <p>{color}</p>;
}

// app/products/page.tsx
export default function Products() {
  return <Filters />;
}

Compliant solution

// app/products/page.tsx
import { Suspense } from 'react';

export default function Products() {
  return (
    <Suspense fallback={<p>Loading filters</p>}>
      <Filters />
    </Suspense>
  );
}
