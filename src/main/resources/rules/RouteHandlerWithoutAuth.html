A route handler (app/**/route.ts or route.js) exporting POST, PUT, PATCH or DELETE that changes data (a database write, a POST, PUT, PATCH or DELETE fetch, a revalidation) and checks neither the session nor a token can be called by anyone.

A session call (auth(), getServerSession, currentUser...), a project helper that makes one, a header or cookie read, a secret or token from the environment, or a signature check counts as a check. Auth, webhook, cron and other public-by-design paths are left out, and so are apps without sign-in (no auth library, no sign-in route: their data is public by design) and handlers whose app has a middleware that checks the session and whose matcher covers them. A middleware matcher leaving /api out does not guard the handlers.

Why is this an issue?

Route handlers are public URLs. Without a check, anyone who finds the URL can create, change or delete the data behind it.

Noncompliant code example

// app/api/items/route.ts
export async function DELETE() { // Noncompliant
  await db.item.deleteMany();
  return new Response(null, { status: 204 });
}

Compliant solution

// app/api/items/route.ts
export async function DELETE() {
  const session = await auth();
  if (!session?.user.isAdmin) {
    return new Response('Forbidden', { status: 403 });
  }
  await db.item.deleteMany();
  return new Response(null, { status: 204 });
}
