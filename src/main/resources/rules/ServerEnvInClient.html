This rule reports process.env.X reads in client code (a "use client" module, or a module only client modules import) where X does not start with NEXT_PUBLIC_. NODE_ENV, the variables Next.js defines itself and the names declared under env in next.config are allowed. Modules that check typeof window and t3-env schemas are not reported.

Why is this an issue?

Next.js replaces process.env.NEXT_PUBLIC_* with its value when it builds the browser bundle. Every other variable stays on the server: in the browser the read is undefined. The component works during server rendering, then renders differently or fails after hydration, and the bug only shows in the browser.

Noncompliant code example

'use client';

export function Map() {
  const key = process.env.MAPS_KEY; // Noncompliant: undefined in the browser
  return <MapView apiKey={key} />;
}

Compliant solution

When the value may be public, rename the variable with the NEXT_PUBLIC_ prefix. When it is a secret, read it on the server (server component, Server Action, route handler) and pass only what the client needs.

'use client';

export function Map() {
  const key = process.env.NEXT_PUBLIC_MAPS_KEY;
  return <MapView apiKey={key} />;
}
