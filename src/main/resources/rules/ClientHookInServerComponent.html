A module under app/ without "use client", rendered on the server, calls a client hook: useState, useEffect, useReducer, useRef, useContext, useLayoutEffect, useTransition and the other state and effect hooks of react, useFormStatus of react-dom, or useRouter, usePathname, useSearchParams, useParams of next/navigation.

Why is this an issue?

Modules of the App Router are server components unless they, or a module importing them, start with "use client". Server components render once on the server, without state, effects or browser context: Next.js stops the build with "This React hook only works in a Client Component", or the page fails when it renders.

The rule checks App Router convention files and the app/ modules a server module imports. A module reached only from client components is a client component and is not reported. use, useId, useMemo and useCallback work in server components. One issue per module, on the first call.

How to fix it

Add "use client" at the top of the module, or move the interactive part into a small client component and render that from the server component.

Noncompliant code example

// app/page.tsx
import { useState } from 'react';

export default function Page() {
  const [open, setOpen] = useState(false); // Noncompliant
  return <button onClick={() => setOpen(!open)}>Menu</button>;
}

Compliant solution

// app/page.tsx
import MenuButton from './MenuButton';

export default function Page() {
  return <MenuButton />;
}

// app/MenuButton.tsx
'use client';

import { useState } from 'react';

export default function MenuButton() {
  const [open, setOpen] = useState(false);
  return <button onClick={() => setOpen(!open)}>Menu</button>;
}
