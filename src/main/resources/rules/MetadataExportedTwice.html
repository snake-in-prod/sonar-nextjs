An App Router page or layout exports both the metadata object and the generateMetadata function, declared in the file or re-exported from another module.

Why is this an issue?

Next.js takes the metadata of a route segment from one of the two, never both. A page or layout that exports both is refused: the build fails with "You are attempting to export "metadata" and "generateMetadata" from the same file".

The rule looks at page and layout files of the App Router only. Names brought by export * from are not visible, so such files are left alone.

How to fix it

Keep the static metadata object when the values are fixed, or generateMetadata when they depend on params or fetched data. A shared default can stay as a local constant that generateMetadata spreads.

Noncompliant code example

// app/blog/[slug]/page.tsx
export const metadata = { title: 'Blog' };

export async function generateMetadata({ params }) { // Noncompliant
  const { slug } = await params;
  return { title: slug };
}

Compliant solution

// app/blog/[slug]/page.tsx
const defaults = { title: 'Blog' };

export async function generateMetadata({ params }) {
  const { slug } = await params;
  return { ...defaults, title: slug };
}
