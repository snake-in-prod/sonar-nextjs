A page, layout, default.js, generateMetadata, generateViewport or route handler of the App Router reads params or searchParams without awaiting them, in an app whose package.json declares Next.js 15 or later.

Why is this an issue?

Since Next.js 15, params and searchParams are promises. Reading a property of the promise (params.slug, const { slug } = params, { params: { slug } } in the signature) works in Next.js 15 only through a deprecated compatibility layer that logs warnings, and gives undefined once it is removed. Typing them as plain objects hides the problem from the compiler.

Awaiting the value, unwrapping it with React.use, calling then, or passing it on to another function is fine. One issue per name and function, on the first read.

How to fix it

Make the component or function async and await the promise, or call use(params) in a client component. Type the props as Promise<...>. The official codemod next-async-request-api rewrites most cases.

Noncompliant code example

export default function Page({ params }: { params: { slug: string } }) {
  return <h1>{params.slug}</h1>; // Noncompliant
}

export async function GET(req: Request, { params }) {
  return Response.json(await getItem(params.id)); // Noncompliant
}

Compliant solution

export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  return <h1>{slug}</h1>;
}

export async function GET(req: Request, { params }) {
  const { id } = await params;
  return Response.json(await getItem(id));
}
