Data that depends on the user should not go into a shared cache. This rule reports:

  • an unstable_cache callback that reads cookies, headers or the session (auth(), getServerSession(), currentUser(), getSession(), getUser()), or uses such a value from the enclosing function without receiving it as an argument or listing it in the key parts;
  • a "use cache" function or file that reads cookies, headers or the session.

Why is this an issue?

unstable_cache and "use cache" entries are shared by every request. unstable_cache keys only on its key parts and arguments, so a value captured from the enclosing function (a client built with the user's token, the user's id) leaks the first user's result to everyone who asks for the same key. Reading cookies or headers inside a cached scope fails at build or render time, or caches the first visitor's data.

A cached fetch is not reported: the Data Cache keys a fetch on its URL, headers and body, so a token or user id there gives each user an entry of their own.

The rule follows values through variables of the same function. It stays silent on helpers and cached functions defined elsewhere.

How to fix it

Read cookies and the session outside the cached function and pass what the result depends on as an argument or a key part, or do not cache per-user data.

Noncompliant code example

const session = await auth();
const getPlan = unstable_cache(async () => db.plan.find({ where: { userId: session.user.id } }), ['plan']); // Noncompliant

async function getCart() {
  'use cache';
  const id = (await cookies()).get('cart')?.value; // Noncompliant
}

Compliant solution

const session = await auth();
const getPlan = unstable_cache(async (userId) => db.plan.find({ where: { userId } }), ['plan']);
const plan = await getPlan(session.user.id);

async function getCart(id) {
  'use cache';
  return db.cart.find({ where: { id } });
}
