A redirect(), permanentRedirect() (next/navigation), NextResponse.redirect() (next/server) or Response.redirect(), a res.redirect(url), res.redirect(status, url) or res.writeHead(status, { Location: url }) of a Pages Router API route (or of a module typed with NextApiResponse), a router.push() or router.replace() of useRouter() (next/navigation, next/router) or of the next/router Router, or a window.location.href assignment or window.location.assign() / replace() whose target is taken from searchParams, params, form data, the Pages Router query (router.query, req.query), the request body of a route handler or API route (await request.json(), req.body) or the arguments of a Server Action (a field of an object argument, values.callbackUrl, or of an action library's parsedInput), also through a field of an object literal (const data = { next: formData.get('next') }) or of what a zod schema parsed from them (Schema.safeParse({ next: formData.get('next') }).data.next) when the schema accepts any string for that field, with no allow-list or same-origin check.

Why is this an issue?

An open redirect lets an attacker build a link on your trusted domain that sends the visitor to a site of their choice: https://your.app/login?next=https://evil.example. It is used for phishing, and to steal tokens when the redirect follows a sign-in. redirect() and NextResponse.redirect() accept absolute URLs, router.push() navigates to an absolute URL with a full page load, and new URL(value, request.url) keeps the host of an absolute or protocol-relative value.

The rule reports the target when it is the request value itself (a variable or React state holding it, with a fallback such as ?? '/', a cast, String(), new URL(), or a template literal starting with it). It stays silent when the value is compared, tested (startsWith, match), passed to a check (isSafeUrl, allowed.includes) before the redirect in the function, or transformed by a helper, when a fixed path or origin comes first, and when a request value is compared with a server secret before (req.query.secret !== process.env.PREVIEW_SECRET): only who knows the secret gets to the redirect. A schema field restricted with .startsWith(), .regex(), z.enum(), z.literal(), or a refine / transform that checks the path or the host, is not reported; z.string() with .optional(), .min(), .default(), .trim() or .url() accepts https://evil.example and is.

How to fix it

Accept only local paths (starting with one /, not // or /\), or compare the origin of the parsed URL with your own, or map the value to an allow-list.

export default async function Login({ searchParams }) {
  const { next } = await searchParams;
  if (await auth()) {
    redirect(next ?? '/'); // Noncompliant
  }
}

  const to = request.nextUrl.searchParams.get('to') ?? '/';
  return NextResponse.redirect(new URL(to, request.url)); // Noncompliant
}

Compliant solution

const LoginSchema = z.object({
  email: z.string().email(),
  next: z.string().refine((v) => v.startsWith('/') && !v.startsWith('//')).optional(),
});

export default async function Login({ searchParams }) {
  const { next } = await searchParams;
  if (await auth()) {
    redirect(next?.startsWith('/') && !next.startsWith('//') ? next : '/');
  }
}

export async function GET(request) {
  const url = new URL(request.nextUrl.searchParams.get('to') ?? '/', request.url);
  if (url.origin !== request.nextUrl.origin) {
    return NextResponse.redirect(new URL('/', request.url));
  }
  return NextResponse.redirect(url);
}
