dangerouslySetInnerHTML rendering a value from params, searchParams (useSearchParams() too), form data, the Pages Router query or a fetch response without a sanitizer such as DOMPurify, sanitize-html or xss.

Why is this an issue?

React escapes text, but dangerouslySetInnerHTML inserts the string as HTML. A value from the URL lets anyone craft a link that runs script in your origin (reflected cross-site scripting); HTML from another service runs whatever that service, or whoever compromises it, returns. The script can read the page, act as the user and send their data away.

The rule reports the value when it is the request or response value itself, a variable holding it, or a template literal or concatenation containing it. It stays silent when a sanitizer or escape function is applied to the value in the same function, and when the HTML comes from a helper, a prop, React state, JSON.stringify or a renderer it cannot see into.

How to fix it

Render the value as text ({value}), or sanitize the HTML right before rendering it.

Noncompliant code example

export default async function Search({ searchParams }) {
  const { q } = await searchParams;
  return <h1 dangerouslySetInnerHTML={{ __html: `Results for ${q}` }} />; // Noncompliant
}

export default async function Post({ params }) {
  const { slug } = await params;
  const post = await (await fetch(`${CMS}/posts/${slug}`)).json();
  return <article dangerouslySetInnerHTML={{ __html: post.content }} />; // Noncompliant
}

Compliant solution

export default async function Search({ searchParams }) {
  const { q } = await searchParams;
  return <h1>Results for {q}</h1>;
}

export default async function Post({ params }) {
  const { slug } = await params;
  const post = await (await fetch(`${CMS}/posts/${slug}`)).json();
  return <article dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(post.content) }} />;
}
