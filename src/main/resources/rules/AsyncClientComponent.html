The default export of a "use client" module is an async component.

Why is this an issue?

Only server components can be async functions. React renders client components synchronously, in the browser and during server rendering: an async client component returns a promise instead of elements, which fails with an error or renders nothing, and refetches on every render.

The rule reports the async default export of a "use client" file when it is a component: a PascalCase name, a page, layout or other App Router convention file, or an anonymous export in a .jsx or .tsx file. A lower-case async default export such as a data fetcher is left alone.

How to fix it

Fetch the data in a server component and pass it as props, or remove "use client" when the component needs no browser API. In a client component, load data in an effect, with a data fetching hook, or with use() on a promise passed from the server.

Noncompliant code example

'use client';

export default async function Profile({ id }) { // Noncompliant
  const user = await fetch(`/api/users/${id}`).then((r) => r.json());
  return <p>{user.name}</p>;
}

Compliant solution

// app/profile/page.tsx, a server component
export default async function Page() {
  const user = await getUser();
  return <Profile user={user} />;
}

// Profile.tsx
'use client';

export default function Profile({ user }) {
  return <p>{user.name}</p>;
}
