An exported function of a "use server" module is a Server Action: Next.js gives it an ID and accepts a POST request for it from anyone, whether or not a page of the app shows the form or button that calls it. An action that changes data (a database write, a POST, PUT, PATCH or DELETE fetch, or an awaited helper followed by revalidatePath or revalidateTag) without checking the session can be called by any visitor, signed in or not. An action that only revalidates refreshes the cache and changes no data.

The rule follows the project helpers the action calls: a helper that calls auth(), getServerSession, currentUser, getUser, getSession or reads the session cookie counts as a check. Sign-in, sign-up, password, contact, newsletter and view counter actions are public by design and are left out, and so is an action calling a project helper the analysis cannot see. An app that never checks a session anywhere has no signed-in users: its actions are public by design and are left out too.

Why is this an issue?

Hiding the button from signed-out users, or protecting the page with middleware, does not protect the action: the request can be sent to any page of the app. Each action has to check who calls it, as a route handler would.

Noncompliant code example

'use server';
import { db } from '@/lib/db';

export async function deletePost(id: string) { // Noncompliant
  await db.post.delete({ where: { id } });
}

Compliant solution

'use server';
import { auth } from '@/auth';
import { db } from '@/lib/db';

export async function deletePost(id: string) {
  const session = await auth();
  if (!session) {
    throw new Error('Unauthorized');
  }
  await db.post.delete({ where: { id, authorId: session.user.id } });
}
