This rule reports reads of NEXT_PUBLIC_ environment variables whose name says they hold a secret: a name ending with SECRET or PASSWORD, or with PRIVATE_KEY, SERVICE_ROLE_KEY, SERVER_TOKEN, SECRET_KEY. Names saying PUBLISHABLE, ANON or PUBLIC, and ids, are meant for the browser and are not reported.

Why is this an issue?

Next.js inlines every NEXT_PUBLIC_ variable into the JavaScript sent to the browser. Anyone can read it from the page source: a secret key, a database password or a Supabase service role key exposed this way gives every visitor full access to the service it protects. The key has to be rotated once it has been shipped.

Noncompliant code example

'use client';

const stripe = new Stripe(process.env.NEXT_PUBLIC_STRIPE_SECRET_KEY); // Noncompliant

Compliant solution

Keep the secret in a variable without the prefix and use it only in server code (a route handler, a Server Action or a server component). The browser gets the publishable key, or calls the server.

// app/api/checkout/route.ts
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);

// components/Checkout.tsx
'use client';
const publishableKey = process.env.NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY;
