The arguments of a Server Action, FormData included, come from the client as they are: TypeScript types are not checked at run time. Passing one of them, or a value built from one, to a database call or as the whole target of redirect() without a schema parse (zod, valibot, yup, arktype .parse / .safeParse) or explicit checks lets a caller send any shape or value.

Why is this an issue?

A caller can add fields the form never had (role: 'admin' through Object.fromEntries(formData)), send an object where a string was expected (NoSQL operators such as { $ne: null }), an over-long value, or a redirect to another site. The rule stays silent when the action calls a validation function or tests an input in a condition, a comparison, typeof or an allow-list.

Noncompliant code example

'use server';
export async function updateProfile(formData: FormData) {
  await db.user.update({ where: { id }, data: Object.fromEntries(formData) }); // Noncompliant
}

Compliant solution

'use server';
const Profile = z.object({ name: z.string().max(100), bio: z.string().max(1000) });

export async function updateProfile(formData: FormData) {
  const data = Profile.parse(Object.fromEntries(formData));
  await db.user.update({ where: { id }, data });
}
